§2 · Nguyên tắc nền

"Thay tôi làm, nhưng tôi luôn biết" — Ray

Mọi action agent phải tuân 3 cảm giác:

  • Không bất ngờ — quản lý nhận notification NGAY khi agent thao tác thay, kèm diff trước/sau.
  • Không mù — mở Sổ Tay thấy ngay "AI đã chỉnh X lúc Y", không phải chui vào audit log.
  • Không loạn — agent không đè người đang thao tác. Quản lý đang edit field → agent chờ/xin phép, không last-write-wins âm thầm.

Athena: Mỗi agent = người đại diện theo luật của quản lý nó, KHÔNG phải super-user ẩn danh. Quyền trace được = audit được = người thật chịu trách nhiệm. Agent bypass = lỗ hổng kiểm soát.

§5 · Cơ chế thực thi — Athena + Leon

5.1–5.2 · 1 cổng + scope 3 tầng (AND)

Không cho agent gọi thẳng DB. Mọi thao tác: endpoint → check scope → ghi agent_action_log → mới write. Không qua cổng = chặn.

  • Dept scope — agent thuộc dept nào, edit dept đó (Leon = cả 3).
  • Operation scope — read | write | force | approve.
  • Target scope — wip_* = yes · staff = no · bot_settings = core only.

Thiếu 1 tầng = chặn. Không check "Leon được không" mà "Leon + edit checklist + wip_item = được không". VD: /api/tax/config từ Leon → 403. /api/wip/template xoá từ Na → 403, đọc → 200.

5.3 · Chữ ký kép — trigger RULE tự động (không phán đoán)

Bất kỳ edit chạm field photo=true HOẶC priority=critical → tự nâng lên 🟡 (cần 1 confirm từ người ngoài dept), vì đụng audit trail Na cần. Middleware check field, không cần người phán đoán.

5.4 · Audit bất biến · 5.5 · Khoá luân phiên · 5.6 · Trách nhiệm

  • agent_action_log = chỉ nối thêm, không bao giờ xoá (hồ sơ pháp lý). Guardrail core duy nhất.
  • Agent > 5 lần / 2 giờ không có phản hồi → lần 3 nhắc nhẹ · lần 5 tạm khoá chờ xác nhận (Leon chỉnh từ 3→5: giờ rush không phạt sớm).
  • Trách nhiệm: mỗi người chịu phần mình (acted_by chịu hành động · on_behalf_of chịu phân quyền), không "người cuối win".

§6 · Schema mới — THE GATE

agent_action_log (handbook.db)
CREATE TABLE agent_action_log (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  agent_id        TEXT NOT NULL,   -- na|leon|ray|will|claude|nova
  acted_by        TEXT NOT NULL,   -- ai thực sự trigger (delegation: leon)
  on_behalf_of    TEXT,            -- quyền của ai được dùng (audrey)
  dept            TEXT NOT NULL,   -- bep|bar|phucvu|finance|hr|core
  operation       TEXT NOT NULL,   -- read|write|force|approve
  target_table    TEXT NOT NULL,
  target_id       TEXT,
  intensity       TEXT NOT NULL,   -- green|amber|red
  before_value    TEXT,            -- JSON snapshot trước
  after_value     TEXT,            -- JSON snapshot sau
  shift_id        TEXT,
  reason          TEXT,
  status          TEXT NOT NULL,   -- auto|pending_1|pending_2|approved|rejected
  approved_by     TEXT,            -- JSON list (2-confirm: ["audrey","will"])
  created_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

Conflict lock — thêm cột wip_item (Leon)

ALTER TABLE wip_item ADD COLUMN locked_by TEXT;   -- telegram_id đang mở edit
ALTER TABLE wip_item ADD COLUMN locked_at TEXT;   -- lock hết hạn sau 2 phút

Ai mở màn edit → lock. Agent thấy lock còn hạn (≤2') → queue chờ / xin phép, không đè.

§7 · API Endpoints — Leon (xương sống)

POST /api/agent/act — cổng thực thi duy nhất
{
  "agent_id": "leon", "acted_by": "leon", "on_behalf_of": "audrey",
  "action": "edit_checklist_template",
  "dept": "bep", "target": { "table": "wip_item", "id": "bep-dauca#3" },
  "payload": { ... }, "intensity": "amber",
  "reason": "Mùa hè thêm bước kiểm tra tủ lạnh 2 lần/ca"
}

Pipeline middleware (6 bước):

  1. Auth (tái dùng buildBoot) → resolve agent_id + persona dept.
  2. Scope 3 tầng → thiếu 1 = 403.
  3. Conflict lock → target đang lock người khác = 409 + gợi ý queue.
  4. Intensity resolve → nâng tier nếu chạm photo/priority=critical.
  5. Ghi agent_action_log (before/after) với status theo intensity.
  6. Execute / queue. Settle staff.db (nếu cần) qua wip_outbox → bridge.

Response: { ok, action_id, status, intensity, undo_until } · GET /api/agent/audit → SELECT * FROM agent_action_log WHERE dept=? ORDER BY created_at DESC LIMIT 10.

Build được 2 endpoint này = mọi agent đều hoạt động được.

§8 · UI Spec — Ray (experience layer)

Thanh hoạt động AI — cuối mỗi màn, không phải tab riêng

🤖 Leon AI đã đóng ca Bếp 22:15 · Trễ 15 phút [Xem thay đổi] 🤖 Na AI khoá kỳ COGS Q1 · 16:42 [Xem chi tiết] 🤖 Ray AI sửa microcopy tab Duyệt · 14:03 [Xem thay đổi]

Vì sao đặt nơi đang làm việc: nếu Audrey phải vào tab riêng mới thấy AI chỉnh gì → cô ấy sẽ không kiểm tra. Màu theo intensity (border-left 🟢/🟡/🔴), scroll nếu >3 item, unread = chấm đỏ.

Modal diff + Hoàn tác 30'

┌─ Thay đổi ──────────────────────────────┐ │ 🤖 Leon AI · 22:15 · Ca Bếp │ │ Intensity: 🟡 Vàng · Chờ Audrey xác nhận │ │ Trước: Sau: │ │ status: open status: closed │ │ Lý do: "Staff đã đi hết, ca trễ 15p" │ │ [Hoàn tác 29:58] [Đồng ý] │ └──────────────────────────────────────────┘
  • Layout side-by-side (tablet+) / stacked (mobile). Diff: thêm = green bg · xoá = red bg + strikethrough · sửa = amber bg.
  • Countdown chạy từ created_at (server), KHÔNG từ lúc mở modal: 30' − (now − created_at). Hết hạn → mờ nút + "tạo revert action".
  • Nút Đồng ý chỉ hiện khi 🟡 + người xem là approver. 🟢 → "Đã thực hiện". 🔴 → "Xác nhận 1/2".
  • Lý do giới hạn 30': hoàn tác hôm sau = mở lại ca hôm qua = data lộn. 30' = cửa sổ sửa ngay, không phải hồi cố.

§9 · Giọng AI / Identity — Ray

Notification mang giọng của agent đó, không phải giọng hệ thống. Mọi action ghi tên agent, không giấu dưới "system".

  • Leon AI (ops): ngắn, khô. "Đã đóng ca Bếp 22:15 — ca trễ 15 phút do chờ khách cuối."
  • Na AI / Audrey AI: ấm, bao quát. "Em đã cập nhật checklist Ca sáng — thêm bước kiểm tra nhiệt độ tủ mát."
